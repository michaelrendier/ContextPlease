SECTION 1 — WHAT v5.0 MUST BUILD

Two features define v5.0. Both are load-bearing for any external user of PTorrent.

─────────────────────────────────────────────────────────────
1A. USER SPACE
─────────────────────────────────────────────────────────────

WHAT IT IS:
  A first-class sandboxed storage layer that belongs to the user,
  separate from the app's system defaults and the PTorrent chain.
  Every user-owned artifact lives in user space. The app owns nothing
  in user space; it only reads from it with permission.

WHY IT MATTERS:
  Right now every bin, every ptorrent, every key lives in the app's
  extDir(). When the app is updated, config is lost. When multiple
  users want different corpora, they can't. There's no concept of
  "this is mine." v5.0 establishes ownership.

ARCHITECTURE:

  User Space root:  /sdcard/PTorrent/userspace/<orcid_hash>/
  (or configurable in Settings; orcid_hash = SHA256(ORCID)[:12])

  Directory layout:
    userspace/<orcid_hash>/
      profile.json         ← name, ORCID, email (plaintext, user-owned)
      keys/                ← encrypted key store (see 1B)
        keys.enc           ← AES-256-GCM encrypted, Android Keystore key
        keys.iv            ← 12-byte IV (per-write, rotated on every save)
      bins/                ← user's trained corpus bins
        monad_*.bin        ← user's checkpoints
      ptorrents/           ← user's ptorrent library
        *.ptorrent         ← user-curated .ptorrent files
      chain/               ← user's disclosure chain
        ptorrent_chain.json
      scratch/             ← temp files (safe to delete; app clears on startup)

  Key invariants:
    - The app NEVER writes to userspace/ without user action.
    - The app NEVER deletes from userspace/ without explicit user confirmation.
    - profile.json is human-readable. The user can open it in any text editor.
    - The bins/ directory is THE authoritative store — no copies in extDir().
    - userspace/ survives app uninstall IF the user has "preserve storage" on.
      (Android: MANAGE_EXTERNAL_STORAGE or scoped storage with MediaStore.)

  Android storage strategy:
    - API 29+: use getExternalFilesDir() for the app's own data,
      MediaStore or SAF (Storage Access Framework) for user-chosen paths.
    - The Settings screen lets the user pick the userspace/ root via SAF
      (DocumentFile picker). The chosen URI is persisted in SharedPreferences.
    - Default: Environment.getExternalStorageDirectory() + "/PTorrent/userspace/"

  Migration from v4.0:
    On first v5.0 launch, if old extDir() bins exist and no userspace/ exists:
    - Prompt user: "Migrate existing bins to your user space? [Yes / Not now]"
    - On Yes: copy (not move) bins to userspace/<orcid_hash>/bins/
    - Log migration in a migration_log.txt in userspace/scratch/
    - Never auto-delete old bins.

─────────────────────────────────────────────────────────────
1B. USER-DEFINED API KEYS
─────────────────────────────────────────────────────────────

WHAT IT IS:
  Encrypted, per-user, in-app storage for API keys with a Settings UI.
  Replaces the env-var pattern (PTOL_NIST_API_KEY, ANTHROPIC_API_KEY, etc.)
  for the Android app context where env vars are not appropriate.

WHY IT MATTERS:
  The current pattern (api_key_env: "ANTHROPIC_API_KEY" in ptorrent files,
  env vars in the DISCLOSURE_CHECKLIST) is correct for desktop/CLI use.
  On Android there is no shell environment. Keys currently can't be set
  without recompiling or adb tricks. v5.0 makes keys first-class.

ENCRYPTION:
  Android Keystore (hardware-backed TEE where available, software fallback):
    - KeyPairGenerator / KeyGenerator with KeyGenParameterSpec
    - Key alias: "ptorrent_user_keys_v1"
    - Algorithm: AES/GCM/NoPadding, 256-bit
    - IV: 12 bytes, generated fresh on every write, stored beside ciphertext
    - The raw key NEVER leaves the Keystore; only encryption/decryption ops.

  Serialisation:
    keys.enc contains AES-GCM encrypted JSON:
    {
      "anthropic":  "sk-ant-...",
      "openai":     "sk-...",
      "nist_nvd":   "...",
      "github":     "ghp_...",
      "smtp_pass":  "...",
      "custom": {
        "<label>":  "<value>"
      }
    }

  In Python (Chaquopy): read via jnius/pyjnius bridge:
    from jnius import autoclass
    KeyManager = autoclass('com.ptolemy.seeder.KeyManager')
    api_key = KeyManager.get("anthropic")

  KeyManager.java (new class):
    get(String slot) → String | null
    set(String slot, String value) → void
    delete(String slot) → void
    list() → List<String>   ← key names only, not values
    clear() → void          ← wipe all keys (with confirmation dialog)

PYTHON BRIDGE (ptorrent_keys.py — new skills helper):
  """
  skills/ptorrent_keys.py — User API key store (Android Keystore bridge).
  On non-Android (desktop/CI), falls back to os.environ with PTOL_ prefix.
  """

  class KeyStore:
      _SLOTS = {
          'anthropic':  'ANTHROPIC_API_KEY',
          'openai':     'OPENAI_API_KEY',
          'nist_nvd':   'PTOL_NIST_API_KEY',
          'github':     'GITHUB_TOKEN',
          'smtp_pass':  'PTOL_SMTP_PASS',
      }

      def get(self, slot: str) -> str | None:
          try:
              from jnius import autoclass
              KeyManager = autoclass('com.ptolemy.seeder.KeyManager')
              return KeyManager.get(slot) or None
          except Exception:
              # Desktop fallback
              env_var = self._SLOTS.get(slot, slot.upper())
              return os.environ.get(env_var)

      def is_set(self, slot: str) -> bool:
          return self.get(slot) is not None

  # Singleton
  keys = KeyStore()

  Usage everywhere that previously used os.environ.get("PTOL_NIST_API_KEY"):
    from skills.ptorrent_keys import keys
    api_key = keys.get('nist_nvd')  # works on Android and desktop

PTORRENT FILE FORMAT UPDATE (v1.1):
  api_key_env field becomes api_key_slot:
  Before (v1.0): "api_key_env": "ANTHROPIC_API_KEY"
  After  (v1.1): "api_key_slot": "anthropic"
