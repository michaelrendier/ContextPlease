1A. ANDROID APK v2.0 — PTORRENT PROTOCOL (PtolemyHolcus)
─────────────────────────────────────────────────────────
Released as GitHub release v4.0.0 on michaelrendier/PtolemyHolcus.
versionCode 4, versionName "2.0", APK 41MB.

PTorrent file format (.ptorrent):
  A self-contained JSON corpus descriptor — the distribution unit.
  Two delivery paths:
    a) adb push my.ptorrent /sdcard/Android/data/com.ptolemy.seeder.debug/files/inbox/
       FileObserver (CLOSE_WRITE | MOVED_TO) auto-ingests it.
    b) Tap .ptorrent in any file manager → intent filter opens Seeder, queues it.
  Format:
    { "name", "bin", "txt", "primary_tags", "color", "description",
      "urls": [{"tag","url"}, ...] }  ← urls array is optional (embedded)

Corpus detail page (CorpusDetailActivity.kt):
  Tap any corpus card → full-screen detail view.
  Header: name, status chip, description, primary tag chips, bin path.
  Stats grid: Total URLs / Studied / Skipped / Success Rate (live, 2×2).
  URL list: every URL with per-URL status icons:
    ○ PENDING  ▶ ACTIVE  ✓ STUDIED  ✗ SKIPPED
  Incremental update — only changed rows redrawn on LiveData fire.

Transmission toolbar (MainActivity.kt):
  ▶ Resume All  ⏸ Pause All  ✕ Clear Done  ＋ Add PTorrent
  Pause: AtomicBoolean globalPaused checked inside Kotlin Chaquopy bridge __call__.
  Python thread blocks at URL boundary. No Python-side modification needed.

SeedLiveData (SeedService.kt):
  New: urlStates: MutableLiveData<Map<String, List<UrlState>>>
  New: setUrlList(name, urls) / updateUrl(name, idx, status)
  URL pre-population: SeedService parses all .txt files at startup → detail pages
  show full URL list before seeding begins.

FileObserver inbox (SeedService.kt):
  Watches extDir()/inbox/ for .ptorrent drops.
  API-safe: File-based constructor on API 29+, path-based (deprecated) on API 26–28.

seed_runner.py (Android python):
  New: run_one(entry, files_dir, on_progress, check_interval) for single-corpus seeding.
  _seed_one() extracted as shared helper.
  Notification: Pause/Resume toggle action in notification drawer.

corpus_list.json: all 7 entries now have "description" field.
