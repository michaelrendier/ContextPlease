## 1. The space a page has (decide these first)
- **Panels are viewports.** Each panel is a rectangle of CSS pixels with its own backing store: canvas width/height = clientSize x devicePixelRatio, re-set on resize (`resize()` before every frame), `aspect = width/height`.
- **Pick the up axis once.** Python/maths code is z-up; WebGL pages here are y-up. The shipped buffer layout (from the Aizawa page and rhp.strange_path) is positions `[x, z, y]` so z is drawn up. Say it in a comment.
- **Camera = yaw, pitch, distance** about a centre point. mvp = perspective(fov 0.8 rad) * translate(0,0,-dist) * rotX(pitch) * rotY(yaw) * translate(-centre). Pitch 0 = equatorial view; pitch pi/2 = looking down the up axis (the view from the pole). Provide those two buttons, reset (double-click), wheel zoom (`{passive:false}`), pointer drag with `touch-action:none`, and a "link cameras" toggle when two panels compare.
- **One parameter along a path.** Geometry is (positions Float32Array(3n), param Float32Array(n)); param = i/n colours the path (rainbow) and also drives growth animation: draw the first `count` vertices.

## 3. Rules learned by failing (each one was measured)
1. **Additive glow saturates.** 400,000 points at alpha 0.3 is a white disc. Scale alpha with the point count (alpha ~ K / count, clamp 0.05..0.5) and draw every 3rd point for dense paths (order and growth are kept).
2. **A sampling lattice draws fake structure.** Sampling a rotating curve at equal phase steps puts every point on a few fixed angles: 32 rigid spokes appeared that were not in the curve. Jitter the phase grid (golden-ratio offset), or draw lines.
3. **file:// pages cannot `fetch()` local files in Firefox.** Bake data into a `<script src="x_data.js">` as base64 Float32Array text (`window.X = {...}`); it works offline and from a local server.
4. **Headless Firefox does not capture WebGL canvases.** The screenshot shows black while `gl.readPixels` reports lit pixels. Verify with (a) `preserveDrawingBuffer:true`, (b) a lit-pixel count written into the DOM, (c) a `?snap=1` option that replaces each canvas by an `<img src=canvas.toDataURL()>` so a screenshot shows it.
5. **Make errors visible in the DOM** (shader log, `gl.getError()`, WebGL version) - a black canvas gives no other clue.
6. `gl_PointCoord` is undefined for lines: round-point discard needs a uniform that is 0 when drawing lines.
7. Data wider than the panel: set `aspect-ratio` on the canvas wrapper, not fixed pixel sizes; two columns above 800 px, one below; 16 px gutters.
8. **Show a curve as a curve.** A frame of dots is not a path: default to `LINE_STRIP` for paths, draw sub-ranges with `drawArrays(mode, first, count)` (block-by-block views), and re-map the colour parameter per block (`uTmap`) so a block shows its own direction.
9. **One LINE_STRIP joins everything in the buffer.** Several rings in one buffer get joined by long straight lines; draw each ring with its own `first`/`count`.
10. **Pick a height scale that gives early frames room.** A chart whose height is t had the first 236 of 21,942 units squeezed into 1% of the height; use ln t.
11. **Check that a grid resolves what it plots.** A spectrum on 1,800 grid points aliased spikes 4.5e-5 wide; evaluate at the known positions instead.
12. **Animations: one step per second means a timer, not requestAnimationFrame.** Keep rAF for camera redraws, `setInterval(…, 1000)` for the steps; give play/pause/step/scrub, and URL options (`?step=&block=1&play=0`).
13. Do not run someone else's JavaScript to "see what it does": read it. (The harness blocked executing a downloaded page; the equations were verified by reading and by an independent Python port.)

## 8. CherryPy: the loopback web API behind a page (added 2026-11-28; Cody uses it for the PTorrent browser version)
CherryPy 18.10 (pure Python, threaded, no framework) is the web API server. It is installed in `ValaQuenta/.venv` and `PtolemyDesktop/.venv`; tutorials and a test are in `Ptolemy2/Mouseion/cherrypy/tut01…tut12.py`. The recipe below was **run and checked** (index, JSON GET and POST, Range 206, server-sent events, JSON error page) on 2026-11-28.
- **Serve the page and the API from ONE app, one port.** Same origin means no CORS, and it removes the `file://` problems of §3 rule 3: the page `fetch()`es `/api/...` and the favicon works (§ standing rule 5). Bind **127.0.0.1** only (`server.socket_host`), never 0.0.0.0 unless Cody says; one port per gallery (8765–8795 are taken: check `ContextPlease/claude/galleries/build_index.py`). Turn autoreload off (`engine.autoreload.on: False`) and the screen log off for a background server.
- **Skeleton.**
```
import cherrypy
from cherrypy.lib import static
class Api:
    exposed = True                                   # MethodDispatcher: one class per resource, one method per HTTP verb
    @cherrypy.tools.json_out()
    def GET(self, name=None, **kw): return {"hello": name or "world"}
    @cherrypy.tools.json_in()
    @cherrypy.tools.json_out()
    def POST(self): body = cherrypy.request.json; return {"sum": sum(body.get("xs", []))}
class Root:
    api = Api()
    @cherrypy.expose
    def files(self, name): return static.serve_file(path_for(name))      # Range, If-Modified-Since, Content-Length for free
    @cherrypy.expose
    def events(self):                                                      # progress with server-sent events (no WebSocket library needed)
        cherrypy.response.headers["Content-Type"] = "text/event-stream"
        def gen():
            for i in range(3): yield f"data: {json.dumps({'step': i})}\n\n"
        return gen()
    events._cp_config = {"response.stream": True}
conf = {"/": {"tools.staticdir.on": True, "tools.staticdir.dir": PAGES, "tools.staticdir.index": "index.html", "error_page.default": error_json},
        "/api": {"request.dispatch": cherrypy.dispatch.MethodDispatcher()}}
cherrypy.config.update({"server.socket_host": "127.0.0.1", "server.socket_port": 8801, "engine.autoreload.on": False, "log.screen": False, "server.thread_pool": 8})
cherrypy.tree.mount(Root(), "/", conf); cherrypy.engine.start(); cherrypy.engine.block()      # in a test: start(), call, then engine.exit()
```
- **Rules that came out of running it.** (1) Return a *generator* and set `response.stream = True` (via `_cp_config`) for anything large or long; otherwise CherryPy buffers it all. (2) `static.serve_file` is the way to hand out data files (PTorrent shards, FITS, .bin): it answers `Range` with 206 and `Content-Range`, which a browser needs for seeking and resuming. (3) JSON errors for the page: set `error_page.default` to a function returning `json.dumps({"error": status, "detail": message})` so `fetch()` can read failures. (4) A handler that takes more than a second belongs in a background thread (`cherrypy.process.plugins.BackgroundTask`/`Monitor`) with progress polled from `/api/status` or pushed over SSE: the thread pool is small. (5) CORS is needed only if the page comes from another origin; then add a `before_handler` tool that sets `Access-Control-Allow-Origin` to that exact origin and answer `OPTIONS`. (6) Every outbound request the server makes carries the Mozilla user agent (standing rule); the page itself makes no network call except to its own API, so it works offline.
- **The page side.** `fetch('/api/x').then(r => r.json())`; keep the §1 viewport model (panels, `resize()`, aspect) unchanged; put the page's **JS-vs-Python self-check** behind `/api/selfcheck` (the page sends what it computed, the server compares with the Python engine and returns the verdict), the same convention as the galleries (`#selfcheck`).
- **Test it like the rest.** Start the server in a thread, call it with `urllib`, `cherrypy.engine.exit()`; assert status codes, JSON, `Content-Range`. Then screenshot with headless Firefox over `http://127.0.0.1:PORT/` (§6). **Commit and push** a finished page and its API module (standing rule 2).
